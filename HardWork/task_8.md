## 1) Паттерн Visitor в ООП

Ознакомился с материалом «Паттерн Visitor в ООП».

Для себя ассоциативно запомнил как **гость, которому везде «рады»**: то есть для него в каждом классе предусмотрена программа обработки.

Очень напомнило лично мне **полиморфизм**, однако в данном случае паттерн более функционален с точки зрения содержания: классы закрыты с точки зрения доработки, просто лишь дополняем визитёра нужными методами.

## 2) Про примеси / миксины

В Питоне миксин — это универсальный метод, который можно использовать при множественном наследовании чисто для устранения дублирования кода. По логике своей он может быть использован вместо `accept` для классов, которые посещает визитёр.

То есть **визитёр — это архитектурный паттерн**, а вот **миксин — это механизм повторного использования**.

В джанго-проектах активно использовались миксины.
