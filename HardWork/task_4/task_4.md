def replace_numbers(text):

    # Обрабатываем текстовые числительные
    words = re.findall(r"[\w'ʻ]+|[.,!?;:]|\s+", text)
    new_text = text
    i = 0
    sequence_valid = True

    while i < len(words):
        original_word = words[i]
        if original_word.isspace() or original_word in ['.', ',', '!', '?', ';', ':']:
            i += 1
            continue
        normalized_word, suffix = normalize_number_word(original_word.lower())

        if normalized_word in STOP_WORDS:
            i += 1
            continue

        if i + 2 < len(words):
            next_word = words[i + 2]

            # Проверяем варианты через пробел или через дефис
            next_norm, _ = normalize_number_word(next_word.lower())
            combined_space = f"{normalized_word} {next_norm}"  # bir xil
            combined_dash = f"{normalized_word}-{next_norm}"  # bir-xil

            if combined_space in STOP_WORDS or combined_dash in STOP_WORDS:
                i += 3  # пропускаем оба слова (bir + пробел + xil)
                continue

        if normalized_word in number_map:
            number_sequence = [normalized_word]
            original_sequence = [original_word]
            has_suffix = bool(suffix)
            j = i + 1

            while j < len(words):
                next_original = words[j]
                # Пропускаем только пробелы в последовательности
                if next_original.isspace():
                    j += 1
                    continue

                # Прерываем на пунктуации (кроме запятых в числах)
                if next_original in ['.', '!', '?', ';', ':']:
                    break
                next_norm, next_suffix = normalize_number_word(next_original.lower())

                if next_norm in STOP_WORDS:
                    break

                if next_norm not in number_map:
                    break

                if has_suffix:
                    break

                if next_norm in number_map:
                    if len(number_sequence) >= 4:
                        break
                    number_sequence.append(next_norm)
                    original_sequence.append(next_original)
                    j += 1
                else:
                    break

            if number_sequence and sequence_valid:
                if len(number_sequence) >= 4:
                    individual_numbers = []
                    for word in number_sequence:
                        value = number_map[word][0]
                        individual_numbers.append(str(value))
                    number_value = ' '.join(individual_numbers)

                # Преобразуем числительную часть в цифры
                number_value = convert_number_sequence(number_sequence)


                # Определяем регистр
                first_original = original_sequence[0]
                if first_original.isupper():
                    number_str = str(number_value).upper()
                elif first_original[0].isupper():
                    number_str = str(number_value).capitalize()
                else:
                    number_str = str(number_value)

                # Сохраняем суффикс от последнего слова
                last_original = original_sequence[-1]
                _, last_suffix = normalize_number_word(last_original.lower())

                # Формируем замену: число + суффикс
                if last_suffix:
                    if last_suffix.startswith('-'):
                        replacement = f"{number_value}{last_suffix}"  # "3-siga"
                    else:
                        replacement = f"{number_value} {last_suffix}"  # "5 ta"
                else:

                # Заменяем в тексте
                pattern = r"(?i)\b" + r"\s+".join(re.escape(word) for word in original_sequence) + r"\b"
                new_text = re.sub(pattern, replacement, new_text, count=1)

            i = j
        else:
            i += 1

    return new_text

Известные слитные формы распознаются по заранее заданным соответствиям. Защищённые слова возвращаются без изменений.

#### Соответствие реализации дизайну

Общее назначение реализовано, однако сохранность исходного текста обеспечена не полностью.

**1. Токенизация теряет числа и некоторые слова.**

```python
tokens = re.findall(
    r'\b[А-Яа-яЁёA-Za-z]+\b|[^\w\s]|\s+',
    text,
)
```

Данная регулярка выделяет слова из перечисленных букв, знаки препинания и пробельные символы, но не сохраняет цифровые токены.

Ветка «не кириллица — оставляем как есть» работает только с уже найденными токенами. Символы, которые регулярка пропустила, в результат не возвращаются.

Проверка с переводчиком-заглушкой, возвращающим `salom`:

| Исходный текст | Результат |
| --- | --- |
| `Номер 0056!` | `Salom !` |
| `ID A12 0056!` | `ID  !` |
| `сўм` | пустая строка |

Таким образом, реализация нарушает гарантию сохранения участков, не предназначенных для перевода.

Перспективное изменение — находить только переводимые участки и заменять их по позициям, сохраняя весь остальной текст. При этом нужно определить границы слова и правила для смешанных буквенно-цифровых идентификаторов.

**2. Кэширование не учитывает нормализацию регистра.**

```python
if token in translation_cache:
    translated = translation_cache[token]
else:
    translated_lower = GoogleTranslator(
        source='ru',
        target='uz',
    ).translate(token.lower())

    translation_cache[token] = translated_lower
```

Ключом кэша является исходный токен, хотя переводчику передаётся его нижний регистр.

Для последовательности:

```text
Привет ПРИВЕТ привет ПрИвЕт
```

выполняются четыре обращения с одинаковым словом `привет`.

Следует определить контракт кэширования: базовый перевод хранится по нормализованному слову, а оформление регистра выполняется после получения перевода. Если языковые настройки могут меняться, они также должны учитываться в ключе.

**3. Статистика учитывает не все обработанные вхождения.**

Счётчик изменяется только при успешном запросе вне кэша:

```python
stats_cyr["file"][token] = (
    stats_cyr["file"].get(token, 0) + 1
)
```

Для текста `привет привет` переводятся два вхождения, но счётчик увеличивается один раз.

Нужно явно определить, что измеряется:

- количество переведённых вхождений;

- количество обращений к переводчику;

- количество уникальных слов;

- количество попаданий в кэш.

Текущая реализация не обязательно ошибочна, если требуется считать успешные запросы вне кэша. Но это значение нельзя без уточнения интерпретировать как число всех переведённых слов.

**4. Обработка ошибок смешана со статистикой.**

В одном `try` находятся обращение к переводчику, запись в кэш и обновление статистики. Ошибка счётчика может быть воспринята как ошибка перевода.

При этом операции изменения регистра находятся вне `try`. В проверке с ответом переводчика `None` возник `AttributeError`.

Следует определить допустимый ответ переводчика и отделить сбой внешнего сервиса от ошибок диагностического учёта. Ошибка статистики не должна незаметно менять предметный результат.

**5. Сохранение регистра требует уточнения.**

Для смешанного регистра, например `ПрИвЕт`, исходное расположение заглавных букв не восстанавливается. В проверке получен строчный перевод.

Кроме того, `.title()` изменяет начало каждого слова многословного перевода. Это отличается от правила «сделать заглавной только первую букву всего результата».

Необходимо описать, какие варианты регистра поддерживаются и что происходит в остальных случаях.

**6. Замер времени сохраняет только последний вызов.**

```python
timings["translate_cyrillic"] = time.time() - start
```

При обработке нескольких записей предыдущее значение перезаписывается. Это соответствует времени последнего вызова, но не суммарному времени перевода набора.

Нужно определить назначение замера. Для измерения длительности предпочтителен монотонный счётчик, например `time.perf_counter()`.

#### Вывод по функции

Функция объединяет перевод, восстановление регистра, кэширование, статистику и измерение времени.

Первоочередное изменение — устранение потери исходного текста. Затем следует уточнить контракты перевода и кэширования и отделить предметное преобразование от диагностических операций.

Также нужно явно различать перевод с русского на узбекский и транслитерацию кириллицы. Это разные задачи, хотя обе могут менять алфавит результата.

### 7) def process_text_pipeline(text_orig)

Функция организует обработку одной транскрипции. Она последовательно вызывает включённые этапы и возвращает обработанный текст.

В текущей конфигурации выполняются:

1. Нормализация апострофов.

2. Преобразование словесных числительных.

3. Нормализация пробелов вокруг пунктуации.

4. Финальная очистка пробелов.

Перевод кириллицы отключён.

#### Соответствие реализации дизайну

**1. Порядок нормализации апострофов и замены чисел обоснован.**

```python
processed = normalize_apostrophes(processed)
processed = replace_numbers(processed)
```

Первый этап подготавливает представление слов для распознавания по словарям. Этот порядок является частью дизайна взаимодействия компонентов: перестановка вызовов не обязана сохранять результат.

**2. Перевод не участвует в активной обработке.**

```python
# processed = translate_cyrillic(processed)
```

Поэтому обнаруженная потеря цифр в `translate_cyrillic` сейчас не означает, что активный пайплайн удаляет числа.

В локальной проверке строка `Привет 0056` сохранилась без обращений к переводчику.

Однако при включении перевода после преобразования числительных полученные цифры могут исчезнуть. Это нарушение совместимости этапов: последующий компонент уничтожает результат предыдущего.

Просто переносить перевод перед заменой чисел тоже нельзя без анализа: перевод способен изменить слова, которые ожидает словарь числительных.

**3. Финальная очистка дублирует предыдущий этап.**

```python
processed = fix_punctuation_spacing(processed)
processed = re.sub(r' {2,}', ' ', processed).strip()
```

Текущий `fix_punctuation_spacing` уже схлопывает последовательности пробельных символов и удаляет их по краям текста.

При сохранении этого контракта дополнительная очистка избыточна. Это подтверждено на примерах с пробелами, табуляцией, переносами строк, пунктуацией и пустым текстом.

Возможное упрощение:

```python
processed = normalize_apostrophes(text_orig)
processed = replace_numbers(processed)
return fix_punctuation_spacing(processed)
```

**4. Конфигурация этапов не выражена явно.**

Перевод включается и отключается комментированием строки. Для экспериментального скрипта это допустимо, но для воспроизводимого запуска нужно сохранять конфигурацию активных этапов.

Также следует закрепить строковый тип входа и определить, где проверяются отсутствующие или некорректные значения.

#### Вывод по функции

Функцию целесообразно оставить небольшим оркестратором. Основное улучшение заключается в согласовании контрактов этапов, явной конфигурации и устранении дублирования.

Само наличие нескольких последовательных вызовов не требует дополнительной системы классов.

### 8) def main()

Функция организует обработку набора транскрипций: загружает данные, выбирает эталон, запускает обработку текста, сохраняет результаты и формирует отчёт о качестве.

Выбор эталона, смысл метрик, правила накопления статистики и политика сохранения должны быть определены независимо от технической реализации.

#### Соответствие реализации дизайну

**1. Пустая ручная правка считается отсутствующей.**

```python
if item.get("edited_replaced_text"):
    replaced_ref = item.get("edited_replaced_text")
else:
    replaced_ref = item.get("replaced_text", "")
```

Проверяется истинность значения, а не наличие поля.

Если пустая строка означает «ручной правки нет», поведение допустимо. Если редактор намеренно удалил транскрипцию целиком, код ошибочно вернётся к прежнему эталону.

Следует определить смысл пустого значения и отдельно описать оценивание пустого эталона.

**2. Условия пригодности входных данных не заданы явно.**

```python
text_orig = item.get("text", "")
```

Отсутствующее поле даст пустую строку, но `text=None` останется `None`.

Также код предполагает, что входной JSON содержит список словарей. Нужно определить правила валидации и исходы ошибок: пропуск записи, её маркировка или остановка всего запуска.

**3. Средний WER по записям отличается от WER всего набора.**

```python
avg_wer = sum(wer_list) / len(wer_list)
```

Так рассчитывается невзвешенное среднее индивидуальных WER среди оценённых записей.

Например:

- первая запись: одна ошибка на одно слово;

- вторая запись: ноль ошибок на девять слов.

Среднее по записям равно `0.5`, а отношение общего числа ошибок к общему числу слов — `0.1`.

Обе характеристики могут быть полезны, но необходимо явно назвать выбранную метрику и указать число оценённых и пропущенных записей.

**4. Сравнение через `zip` не объясняет ошибки WER.**

```python
for rw, mw in zip(ref_words, my_words):
    if rw != mw:
        mismatch_counter[rw] += 1
```

Пример:

```text
Эталон:    a b c
Результат: a x b c
```

Произошла вставка `x`, но позиционное сравнение отмечает несовпадения для `b` и `c`. Слова в хвосте более длинной последовательности могут вообще не учитываться.

Для диагностики замен, вставок и удалений нужно выравнивание последовательностей. Иначе статистику следует называть именно позиционными несовпадениями, а не объяснением ошибок WER.

**5. Глобальные счётчики не сбрасываются внутри запуска.**

Локальные `wer_list` и `mismatched_entries` создаются заново, а `mismatch_counter`, `timings` и другие объекты используются извне.

При двух вызовах `main()` в одном процессе счётчик расхождений в проверке накопил значения предыдущего запуска.

Необходимо определить область жизни каждого объекта: одна запись, один файл, один прогон или вся сессия. Кэш может жить дольше отчёта, но статистика должна учитывать это явно.

**6. Перезапись входного файла не защищена от неполного сохранения.**

```python
with open(
    "corrected_text_replacements.json",
    "w",
    encoding="utf-8",
) as out_f:
    json.dump(data, out_f, ensure_ascii=False, indent=2)
```

Файл обрезается при открытии на запись. Если сохранение прервётся, он может остаться неполным.

Возможные решения — отдельный выходной файл либо запись во временный файл с последующей заменой. Политика сохранения относится к гарантиям пакетной обработки.

При этом независимое сохранение двух файлов не делает их общей транзакцией.

**7. Диагностическим записям не хватает идентификации.**

В `mismatched_entries` не сохраняются исходная транскрипция и идентификатор записи. Для поиска конкретного случая этого может быть недостаточно.

Порог `0.1` также должен быть обозначен как критерий отбора: файл содержит не все расхождения, а только выбранные по порогу.

**8. Самостоятельные обязанности можно выделить из `main`.**

Целесообразно отдельно оформить:

- загрузку и валидацию;

- выбор эталона;

- обработку записей;

- оценку качества;

- сохранение результатов;

- представление отчёта.

В `main` останется организация этих операций. Это разделение ответственности, а не требование создать определённое число классов.

#### Вывод по функции

Функция выполняет необходимую роль пакетного оркестратора, но часть правил работы с данными и метриками существует только как следствие кода.

Переработку следует начинать с определения этих правил. Простое разбиение большой функции на несколько маленьких не устранит неоднозначность выбора эталона, статистики и поведения при сбоях.
