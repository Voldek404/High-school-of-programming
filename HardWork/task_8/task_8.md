## 2) Про примеси / миксины

В Питоне миксин — это универсальный метод, который можно использовать при множественном наследовании чисто для устранения дублирования кода. По логике своей он может быть использован вместо `accept` для классов, которые посещает визитёр.

То есть **визитёр — это архитектурный паттерн**, а вот **миксин — это механизм повторного использования**.

В джанго-проектах активно использовались миксины.

### Пример: стандартный Django-миксин + множественное наследование

В Django часто есть «базовая» вьюха, и мы добавляем к ней готовое поведение через миксин, не переписывая её. Классический пример — `LoginRequiredMixin`: он требует авторизации перед выполнением вьюхи.

```python
from django.views.generic import TemplateView
from django.contrib.auth.mixins import LoginRequiredMixin

# Миксин LoginRequiredMixin идёт первым в списке наследования,
# чтобы его метод dispatch() сработал раньше, чем у TemplateView.
class ProfileView(LoginRequiredMixin, TemplateView):
    template_name = "profile.html"
    login_url = "/login/"
```

Здесь `ProfileView` наследуется **от двух классов**:
- `LoginRequiredMixin` — даёт проверку авторизации (повторно используемое поведение);
- `TemplateView` — даёт рендер шаблона.

Сам `LoginRequiredMixin` не является полноценной вьюхой — у него нет своего `get()`/`render()`. Он лишь переопределяет `dispatch()` и проверяет `request.user.is_authenticated`. Если пользователь не залогинен — редиректит на `login_url`, не доходя до `TemplateView`. Именно поэтому миксин **ставят первым** в списке наследования: Python вызывает `dispatch()` по MRO (Method Resolution Order), и версия из миксина срабатывает раньше.

Такой же приём применим и к Visitor: можно написать миксин, который реализует `accept()` один раз, и подмешивать его к классам элементов, вместо того чтобы дублировать метод в каждом классе.

```python
# Миксин с универсальным accept для классов-элементов
class VisitorMixin:
    def accept(self, visitor):
        method = getattr(visitor, f"visit_{self.__class__.__name__.lower()}", None)
        if method is None:
            raise NotImplementedError(f"Нет метода для {type(self).__name__}")
        return method(self)

# Классы элементов просто подмешивают миксин
class Circle(VisitorMixin):
    def __init__(self, r):
        self.r = r

class Square(VisitorMixin):
    def __init__(self, side):
        self.side = side
```

Обратите внимание: миксин здесь устраняет дублирование `accept()`, но **сами визитёры** (`AreaVisitor`, `PerimeterVisitor` с методами `visit_circle`, `visit_square`) всё равно пишутся отдельно. Миксин помогает с технической частью, но не заменяет паттерн.
